# 使い方

## エージェントがすること・しないこと

- する：条件に合う警告を取り出し、ソースを調べて真偽を判断し、**すべての警告に修正案と逸脱コメント案の両方**を作る。一覧サマリと詳細レポートを作る。承認された分だけ反映する。
- しない：採用の決定（人が承認列で決める）、承認していない内容の反映、svn のコミット。
- 承認して反映するまで、利用者のワーキングコピーも Coverity も変更しない。

## 実行（/coverity-run）

- 例：`/coverity-run`（既定の条件 `untriaged.yaml`）、`/coverity-run misra.yaml`、`/coverity-run High だけ`、`/coverity-run ビルドで検証して`。
- 未完了の実行があれば、続きから再開するか尋ねる（処理済みは飛ばし、途中とエラー分をやり直す）。
- 終わると `<出力先>/<実行日時>/summary.md` ができる。時間の目安は 1 件あたり数分。
- 自動検証を指定した場合は、全件の調査後にまとめて 1 回ビルド（＋再解析）する（10〜60 分程度）。問題が出た修正案は確信度が自動で「低」になり、一覧の上の方に並ぶ。

## 一覧サマリ（summary.md）の読み方

確信度の低い順に並ぶ。VS Code のプレビューで表として見られる。

| 列 | 意味 |
|---|---|
| 承認 | 利用者が記入する列（推奨案を下書き済み） |
| CID | 警告の番号。`G1（3 件）` は同じ原因のまとまり（グループ） |
| 推奨 / 確信度 | AI の推奨と確かさ。高：根拠がすべてコードで確認できた／中：一部に推定／低：コードだけでは判断できない |
| 見立て | 判断の決め手の 1 行要約 |
| 検証 | 成功 / 失敗 / 警告残 / 新規 n 件 / 適用不可（他の修正案と同じ箇所を変更）/ 未確認（他の修正案のビルドエラーで確認できず）/ -（未実施） |
| ずれ | 解析時のコードと今のコードのずれ（なし / あり / 不明） |
| 詳細 | 詳細レポート `cid/<CID>.md` |

確認のコツ：確信度「高」は見立てに納得できればそのまま承認してよい。「中」「低」は詳細レポートの「3. 真偽の根拠」を見る。

## 詳細レポート（cid/<CID>.md）

1 結論 → 2 警告の概要 → 3 真偽の根拠 → 4 案A: 逸脱 → 5 案B: 修正（差分ファイル `patches/<CID>-fix.patch`）→ 6 自動検証 → 7 処理情報。

## 承認の記入

`summary.md` の承認列に書く：

| 値 | 反映すると |
|---|---|
| `修正` | git：プルリクエストを作成／svn：ワーキングコピーに差分を適用（コミットは利用者）。Coverity には登録しない |
| `逸脱` | Coverity に Classification / Action / Severity と逸脱コメントを登録 |
| `却下` | 何もしない（次回も対象。グループなら次回から 1 件ずつ） |
| 空欄 | 今回は反映しない（あとで記入して反映できる） |

- グループは 1 行で承認する。一部だけ変えたいときは `却下` にする。
- 逸脱コメントの手直しは詳細レポートの「4. 案A: 逸脱」で行う。`<!-- ct:begin deviation -->` と `<!-- ct:end deviation -->` の行は消さない。
- 修正コードを直したいときは、`却下` にして手で直すか、プルリクエスト上で直す。

## 反映（/coverity-apply）

- 実行フォルダを省略すると最新の実行が対象。件数（修正 / 逸脱 / 却下）を見せて同意を得てから反映する。
- 一部が失敗しても成功分は反映済み。原因を直して再実行すると未反映分だけ反映する（二重登録しない）。
