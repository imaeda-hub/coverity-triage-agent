# CERT C / C++ の判断観点（初版）

運用で得た知見を追記していく資料です。

## 考え方

- CERT の規則はセキュリティ上の弱点（CWE）に対応することが多い。攻撃者が入力を制御できる経路かどうかが、判断と優先度の鍵になる。
- 入力の出どころ（外部入力、ファイル、通信、設定値）を `search_source` でたどり、信頼できない値が届くかを確認する。
- 届かない（内部で生成した値だけ）なら、影響は小さい。ただし規則違反そのものが残る場合は、逸脱コメントで説明する。

## よく出る規則

- **INT30-C / INT31-C / INT32-C（整数のオーバーフロー・変換）**：値の範囲をたどって確認する。範囲が保証されていれば誤検知。
- **STR31-C / ARR30-C（バッファ）**：標準チェッカーの OVERRUN と同じ観点で確認する。
- **ERR33-C（エラーの未処理）**：戻り値を無視している。無視して問題ない理由が説明できれば逸脱、できなければ修正（既存のエラー処理に合わせる）。
- **MEM30-C / MEM31-C（解放後の使用・解放漏れ）**：標準チェッカーの USE_AFTER_FREE / RESOURCE_LEAK と同じ観点で確認する。
