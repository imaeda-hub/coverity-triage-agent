# 標準チェッカーの判断観点（初版）

運用で得た知見を追記していく資料です。

## NULL_RETURNS / FORWARD_NULL / REVERSE_INULL

- **誤検知になりやすい形**：呼び出し元が戻り値を事前に保証している、直前に別の関数で検証済み、アサーションや独自のエラーハンドラ（戻らない関数）で止まる。
- 戻らない関数（`abort` 相当の独自関数）を Coverity が認識していない場合は誤検知になる。関数の実装を確認する。
- REVERSE_INULL は「参照した後で NULL チェックしている」。チェックが不要なのか、参照前にチェックすべきなのかを判断する。
- 修正の定石：参照前の NULL チェックと、既存のエラー処理の書き方に合わせた戻り値。

## RESOURCE_LEAK

- 所有権が呼び出し元や構造体に移っていないか（戻り値で返す、構造体のメンバに格納する、登録関数に渡す）を確認する。移っていれば誤検知。
- エラー経路（途中の `return`）でだけ漏れる場合が多い。修正は既存の後始末の書き方（`goto cleanup` など）に合わせる。

## OVERRUN / BUFFER_SIZE / STRING_OVERFLOW

- 添字やサイズの値の範囲を、定義元・呼び出し元までたどって確認する。範囲が保証されていれば誤検知。
- 終端文字の 1 バイトを含めた計算になっているかに注意する。

## UNINIT

- すべての分岐で代入されているかを確認する。Coverity は「到達しない分岐」を見落とすことがある。
- 出力引数で初期化する関数を Coverity が認識していない場合がある。関数の実装を確認する。

## DEADCODE / UNREACHABLE

- 構成（マクロ定義、ビルド設定）によっては到達するコードではないかを確認する。構成依存なら `intentional`。

## MISSING_BREAK

- 意図的なフォールスルーかどうかを、コメントや前後の処理から判断する。意図的なら `intentional`。修正案では、フォールスルーを明示するコメントや属性を、既存の書き方に合わせて入れる。
