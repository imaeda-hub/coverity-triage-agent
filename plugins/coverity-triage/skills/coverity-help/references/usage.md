# 使い方

## AI がすること・しないこと

- する：条件に合う警告を取り出し、コードを読んで本物のバグか誤検知かを調べ、**すべての警告に修正案と逸脱コメント案の両方**を作る。一覧と詳細レポートを作る。人が承認したものだけを反映する。
- しない：どちらを採用するかを決める（人が一覧の承認欄で決める）、承認していないものの反映、svn のコミット。
- 人が承認して反映するまで、作業中のファイルも Coverity も変えません。修正案は、結果の置き場所に用意するコピーの上で作ります。

## 実行（/coverity-run）

- 例：`/coverity-run`（既定の条件 `untriaged.yaml`）、`/coverity-run misra.yaml`、`/coverity-run High だけ`、`/coverity-run 10 件だけ`。
- 最初に、修正用のコピーを置くフォルダの読み書きを 1 回だけ許可します。
- 途中で止まった実行があると、続きから再開するか聞かれます（終わった警告は飛ばし、途中とエラーの分だけやり直します）。
- 終わると `<結果の置き場所>/<実行の日時>/summary.md` ができます。始めたら、終わるまで質問はしません。

## 一覧（summary.md）の読み方

確信度の低い順に並びます。VS Code のプレビューで表として見られます。

| 列 | 意味 |
|---|---|
| 承認 | 人が書く欄。AI の推奨を最初から入れてある |
| ID | 警告の番号（CID）。`G1（3 件）` は同じ原因と思われる警告のまとまり（グループ） |
| 推奨 | AI の推奨（修正 / 逸脱） |
| 確信度 | 高：根拠がすべてコードで確かめられた／中：一部に推定がある／低：コードだけでは決められない |
| 見立て | 判断の決め手の 1 行 |
| 詳細 | 詳細レポート `cid/<ID>.md` へのリンク |

確かめ方のこつ：確信度が「高」で見立てに納得できれば、そのまま承認してかまいません。「中」「低」は詳細レポートの「3. 真偽の根拠」を見ます。

## 詳細レポート（cid/<ID>.md）

1 結論 → 2 警告の概要 → 3 真偽の根拠 → 4 案A: 逸脱 → 5 案B: 修正（差分をそのまま載せてある）→ 6 処理情報。ビルドでの検証（オプション）を使ったときは、6 に「ビルドでの検証」が入り、処理情報は 7 になります。

## 承認の書き方

`summary.md` の承認欄に書きます。

| 値 | 反映すると |
|---|---|
| `修正` | git：ブランチを push してプルリクエストを作る／svn：作業中のフォルダに差分を当てる（コミットは人）。Coverity には書き込まない |
| `逸脱` | Coverity に分類（Classification / Action / Severity）と逸脱コメントを書き込む |
| `却下` | 何もしない（次の実行でも対象。グループなら次から 1 件ずつ調べる） |
| 空 | 今回は反映しない（あとで書いて反映できる） |

- グループは 1 行で承認します。一部だけ変えたいときは `却下` にします。
- 逸脱コメントを直すときは、詳細レポートの「4. 案A: 逸脱」を書き換えます。`<!-- ct:begin deviation -->` と `<!-- ct:end deviation -->` の行は消さないでください。
- 修正のコードを直したいときは、プルリクエストの上で直すか、`却下` にして自分で直します。

## 反映（/coverity-apply）

- 実行を指定しなければ、いちばん新しい実行が対象です。件数（修正 / 逸脱 / 却下）を見せて、同意を得てから反映します。
- 一部が失敗しても、成功した分は反映済みです。原因を直してもう一度 `/coverity-apply` を使うと、残りだけを反映します（二重に書き込みません）。
- プルリクエストは Copilot が作ります。作れないときは、作成画面を開くリンクが示されます。

## プロジェクトの知識（knowledge.md）

- `.coverity-triage/knowledge.md` は、AI が調べる前に読む知識のファイルです。「調査で使う事実」「推奨の方針（修正か逸脱か）」「逸脱コメントの書き方」を 1 項目 1 行で書きます。
- 自分で足したいときは、`/coverity-help 〇〇を知識に追加して` と頼めます（追記する文を見せて、同意を得てから書きます）。
- 知識とコードが食い違うと、AI はコードを優先し、そのことをレポートに書きます。古くなった知識は消してください。
- オプション `options.knowledge_suggestions` を true にすると、反映のあと、人が推奨を変えた・直した点から知識の候補を示します。
