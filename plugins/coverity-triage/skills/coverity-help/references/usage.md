# 使い方

## AI がすること・しないこと

- する：条件に合う警告を取り出し、コードを読んで本物のバグか誤検知かを調べ、**すべての警告に修正案と逸脱コメント案の両方**を作る。一覧と詳細レポートを作る。人が承認したものだけを反映する。
- しない：どちらを採用するかを決める（人が画面の承認欄で決める）、承認していないものの反映、svn のコミット。
- 人が承認して反映するまで、作業中のファイルも Coverity のトリアージ（分類・コメント）も変えません。修正案は、結果の置き場所に用意するコピーの上で作ります。
  - 例外は初回解析（オプション）だけです。使うときは、最初に開いているフォルダでビルドし、解析の結果を Coverity サーバに登録します（人が手で解析して登録していたことと同じです）。

## AI の役割と進め方

`/coverity-run` では、チャットの AI（メイン）が全体を進め、仕事ごとに別の AI（サブエージェント）に任せます。メインは、次にすることを自分で決めません。スクリプト（`ct.py tick`）が決めた順に従います。

| AI | 仕事 | 同時に |
|---|---|---|
| メイン（チャットの AI） | 始める前の確認、サブエージェントの起動、利用者への報告。ソースは読まない | — |
| 取得（`coverity-triage-collector`） | Coverity から警告を検索し、警告経路を取る。Coverity からは読むだけ | 1 つまで |
| 作業（`coverity-triage-worker`） | 警告 1 件（またはグループ 1 つ）を調べ、修正案と逸脱コメント案を作る | 設定 `parallel` の数まで |
| 統合（`coverity-triage-integrator`。オプション） | 調べ終わった作業のうち、同じ原因のものを 1 つにまとめる計画を書く。コードは書かない | 1 つまで |
| 検証（`coverity-triage-reviewer`。オプション） | 出来上がった結果を、1 件ずつ独立に確かめる。結果とコードは変えない | 1 つまで |

進む順番です。オプションの段は、使う設定のときだけ行います（[settings.md](settings.md)）。

1. 初回解析（オプション）：開いているフォルダをビルド・解析し、Coverity サーバに登録する
2. 取得：条件に合う警告を検索する。スクリプトが作業の一覧を作る（同じ原因と思われる警告はグループにする）
3. 取得：全部の作業の警告経路を、まとめて取る
4. 作業：警告を調べる
5. 統合（オプション）：同じ原因の作業をまとめる
6. 検証（オプション）：結果を 1 件ずつ確かめる。直す点があれば、作業の AI に差し戻す
7. ビルドでの検証（オプション）：修正案をまとめてビルドで確かめる
8. 一覧（`summary.html`）を作る

- サブエージェントの定義は、`/coverity-setup` があなたのフォルダ（`~/.copilot/agents`。環境変数 `COPILOT_HOME` があれば、その中の `agents`）に置きます。
- どれかの AI が止まっても、なるべく最後まで進めます（[troubleshooting.md](troubleshooting.md) の「実行が止まったとき」）。

## 実行（/coverity-run）

- 例：`/coverity-run`（既定の条件 `untriaged.yaml`）、`/coverity-run misra.yaml`、`/coverity-run High だけ`、`/coverity-run 10 件だけ`。
- 始めるとすぐ、ブラウザに画面の「監視」が開きます（もう開いていれば、同じ画面を使います）。画面を閉じても実行は止まりません。
- 最初に、修正用のコピーを置くフォルダの読み書きを 1 回だけ許可します。
- 初回解析を使う設定なら、警告を取る前に、ビルド・解析・サーバへの登録をします（下の「初回解析」）。`/coverity-run 最初に解析して` で、その実行だけ使うこともできます。`/coverity-run 解析はしないで` なら、その実行だけ使いません。
- 途中で止まった実行があると、続きから再開するか聞かれます（終わった警告は飛ばし、途中とエラーの分だけやり直します。統合・検証が途中なら、その続きから進めます）。
- 終わると `<結果の置き場所>/<実行の日時>/summary.html` ができ、画面の「結果」に一覧が出ます。始めたら、終わるまで質問はしません。

## 初回解析（オプション）

今まで人が手で行っていた「Coverity で解析して、サーバに登録する」を、`/coverity-run` の最初に行います。

- 開いているフォルダを、そのままビルド → 解析（`cov-analyze`）→ サーバへの登録（`cov-commit-defects`）します。ビルドのコマンドは、ビルドでの検証と同じ設定を使います。
- 登録先は、条件ファイルのストリームです。版（`--version`）には、開いているフォルダの今のコミット（またはリビジョン）を入れます。
- 登録まで終わってから、今までどおりサーバから警告を取ります。手元の解析の結果を、トリアージに使うことはしません。
- 時間がかかります（数十分）。裏で動くので、チャットの AI は少しずつ様子を見て待ちます。設定 `verify.timeout_minutes`（既定 180 分）を過ぎても終わらなければ止めます。
- 失敗したら、トリアージを始めずに止まります（古い警告を調べないため）。失敗した段（ビルド・解析・登録）とログの最後がチャットに出ます。ログ全体は実行フォルダの `analysis/initial.log` です。設定を直して `/coverity-run` で再開すると、初回解析からやり直します。登録まで済んでいれば、再開しても、もう一度は行いません。
- ビルドの生成物と解析の中間ディレクトリは、開いているフォルダの中にできます（手で解析していたときと同じです）。

## 画面（監視・結果・設定）

ブラウザで開く 1 つの画面です。あなたの PC の中だけで動き、ほかの人からは見えません。上のナビで「監視」「結果」「設定」を切り替えます。

- 開くとき：`/coverity-run` が自動で開きます。閉じてしまったときは、同じアドレスを開き直すか、`/coverity-help 画面を開いて` と頼みます。
- 止めるとき：右上のメニューの「サーバを止める」を押します（確認が出ます）。タブを閉じても、設定を保存しても、止まりません。止めても、結果のファイルや設定は消えません。

### 監視

AI の動きを、枠の図（アスキーアート）で見られます。上の枠が全体を進める AI（チャットの AI）、下に並ぶ枠が、その指示で動くものです。下の枠は、実行の順に、初回解析（`initial`）、取得（`collector`）、作業（`worker`。設定 `parallel` の数だけ）、統合（`integrator`）、検証（`reviewer`）です。初回解析・統合・検証はオプションで、使っていないものは出ません。下の図は、作業の枠だけの例です。

```
┌─ MAIN (Copilot) ─────────────── run 20261015-093000 ─┐
│ 状態: 作業を配っている   12/40 完了  エラー 1        │
└──────┬──────────────┬──────────────┬─────────────────┘
       │              │              │
┌──────┴─────┐ ┌──────┴─────┐ ┌──────┴─────┐
│ worker #1  │ │ worker #2  │ │ worker #3  │
│ CID 20003  │ │ G1 (3件)   │ │ CID 20007  │
│ ▶ 修正     │ │ ▶ 判断     │ │ ⚠ 停止?    │
│ ███████░░  │ │ ████░░░░░  │ │ ██░░░░░░░  │
│ 03:12      │ │ 01:40      │ │ 14:05      │
└────────────┘ └────────────┘ └────────────┘
```

| 表示 | 意味 |
|---|---|
| 上の枠の「状態」 | 全体の段階（検索中、作業を配っている、サブエージェントの終わりを待っている、一覧ができた など）と、終わった数・エラーの数 |
| 下の枠の 1 行目・2 行目 | 枠の番号と、調べている警告（CID か、グループの `G1（3 件）`）。空きの枠は「空き」 |
| `▶` の行 | いましていること。警告経路を取得中 → 調査中（コードを読む → 真偽を判断 → 修正を作る → 逸脱を書く → 結果を書く）→ 結果を確かめている。結果に直すところがあれば「結果を直している」 |
| 棒 | 調査の進み具合の目安 |
| 時間 | その警告を調べ始めてからの時間 |
| `⚠ 停止?` | 10 分のあいだ、その警告に動きがありません（初回解析は 30 分。ビルドは長く黙ることがあるため）。止まっているかもしれません（[troubleshooting.md](troubleshooting.md)） |
| `✔` | その段が終わった（初回解析の「登録済み」など） |
| `▶ 代行中` | 取得のエージェントを使えなかったので、チャットの AI が代わりに Coverity から取っている |
| `✖ できず` | 統合・検証などのエージェントが、その仕事をできなかった。実行は止まらずに進む（[troubleshooting.md](troubleshooting.md) の「実行が止まったとき」） |
| `✖ エラー` | その警告で重大なエラーが起きました。下の「重大なエラー」で内容を確かめます |
| 時間の後ろの `×2` など | その警告を調べ直している回数（2 回目から出ます） |
| 枠の色 | 青：動いている／紫：結果を直している・チャットの AI が代わりにしている／黄：止まっているかもしれない・できなかった／赤：エラー／緑：終わった／灰：空き・待ち |

- 「重大なエラー」：赤が重大なエラー（処理できなかった警告、Coverity とのやり取りの失敗、スクリプトのエラーなど）、黄が注意（取れなかった警告経路、ビルドでの検証の問題、`⚠ 停止?` など）。選ぶと詳しい内容が開きます。
- 「最近の動き」：新しい順に、AI とスクリプトがしたことを 1 行ずつ出します。
- 画面は 2 秒ごとに新しくなります（タブが隠れている間は止まります）。
- サブエージェントの細かい動き（コードを読む、真偽を判断 など）は、サブエージェントが書く記録から出します。書かれないときは、スクリプトの記録だけで表示します。

### 結果

実行の一覧 → 一覧 → 詳細の順に見ます。

- 一覧：上に件数（作業の数、修正・逸脱の推奨の数、承認の内訳、確信度 低、エラー）。表は確信度の低い順です。承認欄を選び直すと、すぐ保存されます。推奨から変えた行には印が付きます。
- 詳細：行を選ぶと開きます。左に詳細レポート、右に承認と逸脱の手直しの欄、差分ファイルと修正後のファイルへのリンクがあります（狭い画面では縦に並びます）。

### 設定

`/coverity-setup` の画面と同じです（基本設定、オプション設定、条件、知識、グループ化しない CID）。

## 一覧（summary.html）の読み方

確信度の低い順に並びます。画面の「結果」でも、ファイルをブラウザで開いても、同じ内容を見られます。

| 列 | 意味 |
|---|---|
| 承認 | いまの承認。AI の推奨を最初から入れてある。変えるのは画面の「結果」で |
| ID | 警告の番号（CID）。`G1（3 件）` は同じ原因と思われる警告のまとまり（グループ） |
| 推奨 | AI の推奨（修正 / 逸脱） |
| 確信度 | 高：根拠がすべてコードで確かめられた／中：一部に推定がある／低：コードだけでは決められない。作業の AI の確信度、検証（オプション）の上限、ビルドでの検証（オプション）の結果のうち、いちばん低いものを出す（検証やビルドで上がることはない） |
| 見立て | 判断の決め手の 1 行 |
| 詳細 | 詳細レポート `cid/<ID>.html` へのリンク |

確かめ方のこつ：確信度が「高」で見立てに納得できれば、そのまま承認してかまいません。「中」「低」は詳細レポートの「真偽の根拠」を見ます。

## 詳細レポート（cid/<ID>.html）

結論 → 警告の概要 → 真偽の根拠（警告経路と調査結果）→ 対応の案（案A: 逸脱 と 案B: 修正。広い画面では左右に並ぶ）→ 修正の差分（色分けして、そのまま載せてある）→ 処理情報。ビルドでの検証（オプション）を使ったときは、処理情報の前に「ビルドでの検証」が入ります。検証（オプション）を使ったときは「独立した検証」も入ります（下の「統合と検証」）。差分ファイル（`patches/`）と修正後のファイル（`fixed/`）へのリンクもあります。

一覧と詳細レポートは表示専用です。ファイルを書き換えても、承認や逸脱コメントは変わりません。設定 `options.markdown` を true にすると、同じ内容の Markdown（`summary.md`、`cid/<ID>.md`）も出ます（[settings.md](settings.md)）。

## 統合と検証（オプション）

どちらも既定では使いません。使うときは設定 `agents.integration`・`agents.review` を true にします（[settings.md](settings.md)）。

- 統合：同じ原因だと判断した作業は、新しい作業 `G<番号>` に 1 つにまとまります。元の作業は一覧と反映から外れ、まとめた作業の詳細レポートの「処理情報」に「統合した作業」として出ます。まとめた修正は、元の差分をつなぐか、作業の AI が作り直します。
- 検証：詳細レポートの「独立した検証」に、結果と見解が出ます。

| 検証の結果 | 意味 |
|---|---|
| 合格 | 判定・修正・逸脱コメント・確信度に、直す点が無かった |
| 要確認 | 人に確かめてほしい点がある。確信度に上限が付く（上限より高い確信度は、一覧とレポートで上限まで下がる）。差し戻して直したあとも指摘が残ったときも、要確認になる |
| 差し戻し | 直す点があったので、作業の AI に直させた。直したものを、もう一度確かめる（一覧には、その結果が出る）。差し戻しは作業ごとに設定 `agents.max_rework` 回まで |
| 未検証 | 検証の AI が起動できなかった、途中で止まったなどで、確かめられなかった。確信度は作業の AI のまま |

- 統合・検証を使う実行では、`/coverity-run` が終わって一覧ができるまで、承認を選べません（統合と検証で、結果が変わることがあるため）。

## 承認の入れ方

画面の「結果」で選びます。選んだ内容は実行フォルダの `approvals.json` に保存されます。

| 値 | 反映すると |
|---|---|
| 修正 | git：ブランチを push してプルリクエストを作る／svn：作業中のフォルダに差分を当てる（コミットは人）。Coverity には書き込まない |
| 逸脱 | Coverity に分類（Classification / Action / Severity）と逸脱コメントを書き込む |
| 却下 | 何もしない（次の実行でも対象。グループなら次から 1 件ずつ調べる） |
| 反映しない | 今回は反映しない（あとで選んで反映できる） |

- グループは 1 行で承認します。一部だけ変えたいときは「却下」にします。
- 逸脱コメントを直すときは、詳細の右の欄で Classification / Action / Severity とコメントを直して「保存」します。「AI の案に戻す」で元に戻せます。
- 修正のコードを直したいときは、プルリクエストの上で直すか、「却下」にして自分で直します。
- 反映したあとで承認を変えると、画面に注意が出ます（変えることはできます）。

古い実行（このプラグインの 0.3 までで作った、`approvals.json` の無い実行）は、これまでどおり `summary.md` の承認欄と、`cid/<ID>.md` の「4. 案A: 逸脱」（`<!-- ct:begin deviation -->` と `<!-- ct:end deviation -->` の間）を読みます。画面で承認を選び直すと、そこからは `approvals.json` を使います。

## 反映（/coverity-apply）

- 実行を指定しなければ、いちばん新しい実行が対象です。件数（修正 / 逸脱 / 却下）を見せて、同意を得てから反映します。
- 承認が 1 件も無いときは、画面の「結果」が開くので、承認を選んでから、もう一度 `/coverity-apply` を使います。
- 一部が失敗しても、成功した分は反映済みです。原因を直してもう一度 `/coverity-apply` を使うと、残りだけを反映します（二重に書き込みません）。
- プルリクエストは Copilot が作ります。作れないときは、作成画面を開くリンクが示されます。

## プロジェクトの知識（knowledge.md）

- `.coverity-triage/knowledge.md` は、AI が調べる前に読む知識のファイルです。「調査で使う事実」「推奨の方針（修正か逸脱か）」「逸脱コメントの書き方」を 1 項目 1 行で書きます。
- 自分で足したいときは、`/coverity-help 〇〇を知識に追加して` と頼めます（追記する文を見せて、同意を得てから書きます）。
- 知識とコードが食い違うと、AI はコードを優先し、そのことをレポートに書きます。古くなった知識は消してください。
- オプション `options.knowledge_suggestions` を true にすると、反映のあと、人が推奨を変えた・直した点から知識の候補を示します。
