# Coverity トリアージ

Coverity の警告を AI が 1 件ずつ調べ、警告ごとに **修正案** と **逸脱コメント案** の両方を作ります。
あなたは一覧を見て、どちらにするかを決めるだけです。決めたものだけが反映されます。

## 必要なもの

| もの | 確かめ方 |
|---|---|
| GitHub Copilot CLI（おすすめ）、または VS Code と GitHub Copilot（チャットでエージェントが使えること） | Copilot のチャットが開ける。警告を取る・調べる・まとめる・確かめるエージェントの動きと、初回解析・統合・検証は、Copilot CLI で確かめています |
| git か svn（いつも使っているもの） | `git --version` / `svn --version` |
| 社内の Coverity Connect のアカウントと認証キー | ブラウザで Coverity に入れる |
| Copilot で GPT-6 Luna が使えること | チャットのモデルの一覧に出る |
| （初回解析を使うときだけ）PC で Coverity の解析のツール（`cov-build`・`cov-analyze`・`cov-commit-defects`）が使えること | `/coverity-selftest ④` で確かめられます |

uv（このプラグインが使う Python の道具）は、無ければ準備のときに入ります。

## はじめての準備（20 分ほど）

1. **プラグインを入れる**
   - VS Code：設定 `chat.plugins.marketplaces` に `imaeda-hub/coverity-triage-agent` を足します。拡張機能のビューで `@agentPlugins` を検索し、`coverity-triage` を **Install** します。
   - Copilot CLI：次を実行します。
     ```
     copilot plugin marketplace add imaeda-hub/coverity-triage-agent
     copilot plugin install coverity-triage@coverity-triage-agent
     ```
2. **調べたいリポジトリを開き、チャットで `/coverity-setup` と入力します。** VS Code では `/coverity-triage:coverity-setup` と表示されます。
3. **準備のしかたを選びます。** 最初に「対話で準備する」か「画面で準備する」かを聞かれます。
   - **対話で準備する**：AI の案内に答えます。聞かれるのは次のことだけです。
     - Coverity の URL、プロジェクト名、ストリーム名（チームで最初に使う人だけ。設定はコミットして共有します）
     - Coverity のユーザ名と認証キー（認証キーは、ターミナルに出る伏せ字の欄に入れます。チャットには書きません）
   - **画面で準備する**：ブラウザに設定の画面が開きます。「基本設定」に上と同じ値を入れ、必要なら「オプション設定」でビルドでの検証などを選んで「保存」します。認証キーも画面で入れます。保存したら、チャットで知らせます。画面は閉じずに、そのまま残ります。あとで AI の動きと結果を見るのにも、この画面を使います。
4. **再起動を頼まれたら**、VS Code（または Copilot CLI）を起動し直して、もう一度 `/coverity-setup` と入力します。続きから進みます。

「準備ができました」と出たら終わりです。

## 毎回の使い方

| | すること | 起きること |
|---|---|---|
| 1 | `/coverity-run` と入力する。例 `/coverity-run High だけ`、`/coverity-run 10 件だけ` | ブラウザに画面が開き、「監視」で AI の動きと重大なエラーを見られます。AI は警告を 1 件ずつ調べ、一覧と詳細レポートを作ります。最初に 1 回だけ、修正用のフォルダの読み書きを許可します。始めたら、終わるまで質問はしません |
| 2 | 画面の「結果」で **承認** 欄を見る | AI の推奨が入っています。変えたい行だけ「修正」「逸脱」「却下」「反映しない」から選び直します（選ぶとすぐ保存されます）。行を選ぶと詳細レポートが開き、逸脱コメントを直したり、差分と修正後のファイルを見たりできます |
| 3 | `/coverity-apply` と入力する | 件数を確かめて同意すると、**逸脱** は Coverity に書き込まれ、**修正** はプルリクエストになります（svn は作業中のフォルダに入るので、確かめてコミットします） |

一覧は確信度の低い順に並びます。確信度が「高」で、1 行の見立てに納得できれば、そのまま承認してかまいません。
一覧とレポートの見本：[docs/sample-output](docs/sample-output/README.md)

途中で止まっても、もう一度 `/coverity-run` と入力すると続きから再開できます。
承認して反映するまで、あなたの作業中のファイルも、Coverity のトリアージ（分類やコメント）も変わりません（初回解析を使うときだけ、最初に解析の結果を Coverity サーバに登録します）。

### 選んだときだけ使えること

画面の「オプション設定」か `/coverity-setup` で選びます。どれも、既定では使いません。

| | 起きること |
|---|---|
| 初回解析 | 警告を調べる前に、開いているフォルダをビルド・解析して、Coverity サーバに登録します（今まで手で行っていた解析と登録の代わりです）。数十分かかります。登録が終わってから警告を取ります。失敗したら、調べ始めずに止まり、理由を伝えます。`/coverity-run 最初に解析して`、`/coverity-run 解析はしないで` と入力すると、その回だけ変えられます |
| 統合 | 調べ終わったあと、同じ原因の警告を、別の AI が 1 つにまとめます |
| 検証 | 調べた結果を、別の AI が 1 件ずつ確かめ直します。気になる点があれば、確信度が下がるか、調べ直しになります。結果は詳細レポートの「独立した検証」に出ます |

統合と検証を使うと、時間が延びます。また、`/coverity-run` が終わって一覧ができるまで、承認は選べません。

### 画面について

1 つの画面に、次の 3 つがあります。画面のサーバはあなたの PC の中だけで動き、ほかの人からは見えません。

| 区分 | 見られること |
|---|---|
| 監視 | AI の動き（全体を進める AI と、その指示で警告を取る・調べる・まとめる・確かめる AI。初回解析の進み具合も）を、枠の図で見られます。長く動かない作業には「⚠ 停止?」が出ます。重大なエラーと、最近の動きもここに出ます |
| 結果 | 実行の一覧、警告の一覧、詳細レポート。承認を選び、逸脱コメントを直します。差分ファイルと修正後のファイルも開けます |
| 設定 | 準備のときと同じ設定の画面です |

- ブラウザのタブを閉じても、画面のサーバは止まりません。同じアドレスを開き直すか、`/coverity-help 画面を開いて` と頼むと、また見られます。
- 止めるときは、画面の右上のメニューの「サーバを止める」を押します。

一覧と詳細レポートは HTML のファイル（結果の置き場所の `<実行の日時>/summary.html`、`cid/<ID>.html`）でもあり、画面を使わずにブラウザで開いて読めます。ただし、ファイルを書き換えても承認にはなりません（承認は画面で選びます）。Markdown のファイルも欲しいときは、画面の「オプション設定」で「Markdown も出す」を選びます。

## 困ったとき

- `/coverity-help` に聞いてください。例：`/coverity-help このエラーは何？`、`/coverity-help MISRA だけ調べたい`
- 実行中のエラーは、画面の「監視」の「重大なエラー」で、内容を見られます。
- この PC で正しく動くかは `/coverity-selftest` で確かめられます。結果は `report.md` にまとまるので、うまく動かないときは、その結果のフォルダをプラグインの管理者に渡してください（認証情報などは伏せてあります）。
