# 20001 — RESOURCE_LEAK（High）

## 1. 結論

- 推奨: **修正** ／ 確信度: **高**（警告経路をコードで最後まで追え、根拠がすべてコードにある）
- 見立て: 本物のバグ（fgets() が失敗したとき fp を閉じずに return している）
- 注意: リビジョンのずれ なし

## 2. 警告の概要

| CID | チェッカー | ファイル | 関数 | 行 | Impact | CWE |
|---|---|---|---|---|---|---|
| 20001 | RESOURCE_LEAK | src/reader.c | open_and_read | 20 | High | 404 |

チェッカーの説明: 確保したリソースが、ある経路で解放されていません。

## 3. 真偽の根拠

警告経路（CID 20001）:

1. src/reader.c:15 `alloc_fn` fopen() でリソースを確保
2. src/reader.c:19 `cond_true` fgets() が NULL を返す分岐を通る
3. ★ src/reader.c:20 `leaked_storage` fp を閉じずに return

調査結果:

15 行目で fopen() が成功したあと、19 行目の fgets() が NULL を返すと 20 行目で return し、22 行目の fclose(fp) を通らない。fgets() は空のファイルや読み取りエラーで NULL を返すため、この経路は実際に成り立つ。fp は関数の外に渡されておらず、ほかで閉じられることもない。

- src/reader.c:15 fopen() で開く
- src/reader.c:20 閉じずに return

## 4. 案A: 逸脱

この節の Classification / Action / Severity と逸脱コメントは書き換えられます。「逸脱」で反映すると、書き換えた内容が Coverity に登録されます。

<!-- ct:begin deviation -->
- Classification: Bug
- Action: Ignore
- Severity: Moderate
- 逸脱コメント:

本物の不具合。fgets() が失敗したとき fp を閉じずに戻るため、ファイルハンドルが漏れる（src/reader.c:20）。呼び出しは read_config() からの 1 回だけで、プロセスの終了時に解放されるため、1 回の実行では実害は小さいが、繰り返し呼ばれるとハンドルが尽きるおそれがある。
<!-- ct:end deviation -->

## 5. 案B: 修正

- 概要: fgets() が失敗したときの return の前に fclose(fp) を足す
- 影響とリスク: 読み取りに失敗したときだけ動きが変わる（ファイルを閉じる）。戻り値と呼び出し元への影響はない
- ブランチ: `coverity-fix/cid-20001`
- 差分ファイル: [20001-fix.patch](../patches/20001-fix.patch)

```diff
diff --git a/src/reader.c b/src/reader.c
index ecfe7a8..953c2c7 100644
--- a/src/reader.c
+++ b/src/reader.c
@@ -17,6 +17,7 @@ static int open_and_read(const char *path, char *out)
         return -1;
     }
     if (fgets(out, BUF_SIZE, fp) == NULL) {
+        fclose(fp);
         return -1;
     }
     fclose(fp);
```
