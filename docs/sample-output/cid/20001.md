## 3. 真偽の根拠

### 警告経路（Coverity のイベント）

- src/reader.c:15 `alloc_fn` fopen() でリソースを確保

### 調査結果

15 行目で fopen() が成功した後、19 行目の fgets() が NULL を返すと 20 行目で return -1 し、22 行目の fclose(fp) に到達しない。fgets() はファイルが空の場合や読み取りエラーで NULL を返すため、この経路は実際に成立する。fp は関数外に渡されておらず、所有権の移動もない。

- src/reader.c:15 fopen() で確保
- src/reader.c:20 fclose せずに return
