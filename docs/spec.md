# Coverity トリアージエージェント 仕様書

この文書は「何を作るか」を定めます。「どう作るか」は [design.md](design.md) に書きます。
用語は VS Code・GitHub Copilot・Agent Plugins・MCP の公式ドキュメントの用語に合わせます（9 章）。

## 1. 目的

Coverity の警告のトリアージ（本物のバグか、修正するか、逸脱として登録するかの判断）を、人が 1 件ずつ行う代わりに AI が下調べし、**人の作業時間を減らす**。

## 2. 使う人と使い方

| 項目 | 内容 |
|---|---|
| 使う人 | 複数のチーム・部署の開発者。各自が自分の Windows PC に入れて使う |
| 使う場所 | VS Code の GitHub Copilot（どの Session Target でも動くこと）。Copilot CLI でも動くこと |
| 対象の警告 | たまった大量の未処理の警告と、リリース前などの節目にまとめて出る警告 |
| 今のやり方 | 人が 1 件ずつコードを追い、Coverity の画面でトリアージする。1 件 5〜15 分。結論は修正と逸脱がおよそ半々 |
| 確認のしかた | AI が作った一覧（Markdown の `summary.md`）を VS Code で見て、承認欄を書き換える |

## 3. 成功の基準

| 観点 | 基準 |
|---|---|
| 準備 | 初めての人が、手順書を見て自力で 20 分以内に終えられる |
| 人の確認時間 | AI の結果を見て承認するまで、1 件 5 分以内 |
| AI の推奨の質 | 推奨案がそのまま採用される割合が 9 割以上 |
| 大量処理 | 100 件を、人が張り付かずに一晩で処理できる |

## 4. 前提

| 項目 | 内容 |
|---|---|
| Coverity | Coverity Connect（社内サーバ）。REST API v2 と SOAP API v9 を使う。書き戻しは REST の `PUT /api/v2/issues/triage`（2022.6.0 以降） |
| 対象のコード | C / C++。チェッカーは Coverity 標準、MISRA C / C++、CERT C / C++ |
| バージョン管理 | git（GitHub / GitHub Enterprise）または svn |
| PC | Windows。VS Code と GitHub Copilot が使えること。git または svn が使えること |
| プラグインの形式 | Agent Plugins 1.0。GitHub のリポジトリをマーケットプレイスとして登録して入れる |
| 動かすための道具 | uv（Python とライブラリを用意する道具）。無ければ準備のときに入れる |

## 5. 機能

### 5.1 入口（利用者が `/` で呼ぶスキル）

| 入口 | すること |
|---|---|
| `/coverity-setup` | 準備（uv、設定ファイル、認証情報、サブエージェントの配置）。何度実行してもよく、足りないものだけを補う |
| `/coverity-run` | 条件に合う警告を取り出し、1 件ずつ AI が調べ、修正案と逸脱コメント案を作り、一覧 `summary.md` を作る。途中で止まったら続きから再開する |
| `/coverity-apply` | 一覧の承認欄に従って反映する |
| `/coverity-help` | 使い方・エラー・設定の変更について答える |
| `/coverity-selftest` | 利用者の PC でプラグインが動くかを確かめ、結果を `report.md` にまとめる |

VS Code ではプラグイン名が前に付きます（例 `/coverity-triage:coverity-run`）。

### 5.2 既定で動く機能

1. **警告の取り出し**：条件ファイル（YAML）で絞り込む。項目はプロジェクト・ストリーム（1 回に 1 つ）・チェッカー名（`*` 可）・Impact・トリアージ状態（Classification / Action / Status）。チャットで条件を足せる。1 回の上限件数を設定できる。
2. **グループ化**：同じチェッカーで、同じマクロ・同じ関数・同じ行の警告を 1 つにまとめて調べる。調べて原因が違えば個別に戻す。却下されたグループは次回から個別に扱う。
3. **調査**：警告 1 件（または 1 グループ）ごとに、新しいサブエージェントが調べる。警告経路（イベント）を Coverity から取り、コードを読んで、本物か誤検知かを判断する。プロジェクトの知識のファイル（`knowledge.md`）を読んで参考にする。
4. **2 つの案**：警告の内容にかかわらず、**修正案と逸脱コメント案の両方**を作る。
   - 修正案：最小限の修正、関数の外部仕様を変えない、既存のスタイルに合わせる。制約内で直せなければ、超えた制約と影響範囲を書く。
   - 逸脱コメント案：日本語、見出しなしの文章、「判定区分（誤検知 / 意図的 など）」「理由」「コード上の根拠箇所」「影響がないことの説明」。あわせて Classification / Action / Severity の案。
5. **確信度と推奨**：確信度（高 / 中 / 低）と推奨案（修正 / 逸脱）を付ける。基準はスキル `triage-investigation` に書く。
6. **レポート**：警告ごとの詳細レポートと、一覧 `summary.md` を作る。
   - 一覧は 6 列（承認・ID・推奨・確信度・見立て・詳細）。確信度の低い順。承認欄には推奨案を最初から入れておく。
   - 詳細レポートは「結論 → 警告の概要 → 真偽の根拠 → 案A 逸脱 → 案B 修正 → 処理情報」。修正の差分をレポートの中に直接載せる。
7. **承認と反映**：人が一覧の承認欄に「修正 / 逸脱 / 却下」を書き、`/coverity-apply` で反映する。反映前に件数を見せて同意を得る。
   - 逸脱：Classification / Action / Severity と逸脱コメントを Coverity に書き戻す（詳細レポートで手直しした内容）。
   - 修正（git）：警告ごとのブランチを push し、プルリクエストを作る。
   - 修正（svn）：差分をワーキングコピーに適用する（コミットは人が行う）。
   - 却下：何もしない。
8. **途中からの再開**：進み具合をファイルに残し、止まった実行を続きから再開する。処理できなかった警告は飛ばして記録し、再開時にやり直す。
9. **動作確認**：`/coverity-selftest`。

### 5.3 オプション（設定で有効にしたときだけ動く）

| オプション | 内容 |
|---|---|
| アノテーション | 逸脱案として、ソースに Coverity の注釈コメント（`/* coverity[<イベントのタグ>:FALSE] 理由 */`、意図的は `:FALSE` なし）を入れる差分も作る |
| ビルドでの検証 | 全件の調査のあと、修正案をすべて当てたコードで 1 回ビルド（＋Coverity の再解析）し、問題が出た修正案の確信度を「低」にする |
| 1 つのブランチにまとめる | 修正を警告ごとではなく、承認したものだけを 1 つのブランチにまとめる（git） |
| 知識の追記の提案 | 反映のあと、人が推奨を変えた・手直しした点から、`knowledge.md` に足す知識の候補を示す。人が選んだものだけ追記する |
| 効果測定の記録 | 承認の内訳、推奨どおりに採用された割合、手直しの割合、1 件あたりの処理時間を記録・集計する |

## 6. 守ること

| 項目 | 内容 |
|---|---|
| 承認前は変えない | 人が承認して反映するまで、利用者の作業中のファイルも Coverity も変えない。修正案は、スクリプトが用意する修正用のコピーの上で作る |
| 書き戻しの確認 | Coverity への書き戻しは、反映前の件数の確認と、その内容が確認後に変わっていないことの確認を経てから行う |
| 認証情報 | Coverity のユーザ名・認証キーは環境変数に置く。チャットには入力しない（ターミナルの伏せ字欄で入れる）。GitHub のトークンは使わない（プルリクエストは Copilot の機能で作る） |
| 文字コード | ソースの文字コードの扱いは Copilot と VS Code に任せる。このプラグインのスクリプトは、差分などを作るときに文字コードを壊さない |
| 調査の起点 | 調査は Coverity が解析したリビジョン（スナップショットに記録があれば）で行う。分からなければ手元のコードで調べ、ずれがないかを確かめてレポートに書く。修正案は取り込み先の最新リビジョンで作る |

## 7. 設定と出力

| ファイル | 場所 | 内容 |
|---|---|---|
| 設定 `config.yaml` | 対象リポジトリの `.coverity-triage/`（コミットしてチームで共有） | Coverity の URL、認証情報の環境変数名、git / svn、取り込み先のブランチ、出力先、上限件数、オプションの有無 |
| 条件 `filters/*.yaml` | 同上 | 絞り込み条件（複数用意できる） |
| 知識 `knowledge.md` | 同上 | 調査で使う事実、推奨の方針、逸脱コメントの書き方（1 項目 1 行） |
| グループ化しない CID `no-grouping.yaml` | 同上 | 却下されたグループの CID（自動で追記） |
| 実行フォルダ | 出力先（既定はリポジトリの外の `../coverity-triage-out`）の下に実行ごと | 一覧、詳細レポート、差分ファイル、修正後のファイル、進み具合、操作の記録 |

## 8. 決定の記録

### 8.1 2026-10-05 の振り返りで決めたこと

| No | 決定 |
|---|---|
| 1 | 準備はスキル（`/coverity-setup`）のまま行い、再起動は 1 回にする。再起動のあと、もう一度 `/coverity-setup` を入力するよう案内する |
| 2 | 準備の最初に、「すべて許可」にする手順を案内する |
| 3 | GitHub のトークンは使わない。プルリクエストは Copilot の機能で作る |
| 4 | トリアージ中は、このプラグインのツールだけを確認なしで使えるようにする（できなければ「すべて許可」を案内する） |
| 5 | 一覧は 6 列（承認・ID・推奨・確信度・見立て・詳細） |
| 6 | 修正の差分を詳細レポートに直接載せる。案の順番は「逸脱 → 修正」のまま |
| 7 | 承認欄には、推奨案を最初から入れておく |
| 8 | README は使う人向けの内容だけにする。仕組みの説明は開発者向けの文書に置く |
| 9 | README には「必要なもの」「はじめての準備」「毎回の使い方」「困ったとき」を載せる。Session Target の指定は書かない |
| 10 | MCP サーバは外部システム（Coverity）との通信だけにする |
| 11 | AI がソースを読むときは、組み込みツール（AI が普段使う読み取り・検索の機能）を使う |
| 12 | AI がソースを修正するときも、組み込みツールを使う |
| 13 | 決まった処理（実行フォルダ、グループ化、差分やブランチの作成、レポート、承認の読み取り、反映など）は、スキルに同梱する Python のスクリプトにし、AI がターミナルで実行する |
| 14 | 修正案は、スクリプトが用意する修正用のコピーの上で作る。利用者の作業中のファイルには触れない |
| 15 | サブエージェントのモデルは、公式の書き方で GPT-6 Luna に固定する |
| 16 | 機能は仕様どおりに残す。既定で動くのは最低限にし、それ以外はオプションにする |
| 17 | 文字コードの特別な処理はしない（Copilot に任せる） |
| 18 | グループ化は既定で有効。アノテーション、ビルドでの検証、1 つのブランチにまとめる方式はオプション |
| 19 | 動作確認（`/coverity-selftest`）は既定で使える。知識の追記の提案と効果測定の記録はオプション |
| 20 | 結果はリポジトリの外（既定 `../coverity-triage-out`）に出す |
| 21 | 修正用のコピーもリポジトリの外に置く。`/coverity-run` の最初に、そのフォルダへのアクセスを 1 回だけ許可してもらう |

## 9. 用語

| 用語 | 意味（公式の用語） |
|---|---|
| エージェント | 言語モデルとツールを使って作業する AI。ここでは Copilot のチャットの AI |
| ハーネス | エージェントを動かす仕組み。VS Code では Session Target で選ぶ（Local、Copilot など） |
| サブエージェント | エージェントが作業を任せる別の AI。独立した文脈で動く。ここでは `coverity-triage-worker` |
| スキル | 手順・知識・スクリプトをまとめたフォルダ（`SKILL.md`）。Agent Skills 仕様に従う |
| ツール | エージェントが呼び出す機能。組み込みツール（ファイルの読み書き・検索・ターミナル）と MCP のツールがある |
| MCP サーバ | 外部システムとつなぐツールを提供するプログラム（Model Context Protocol） |
| プラグイン | スキル・MCP サーバ・エージェントをまとめて配布する単位（Agent Plugins 1.0） |
| 承認 | エージェントがツールを使う前に人が許可すること（ツールの承認）。一覧の「承認欄」とは別のもの |
| CID | Coverity の警告の番号 |
