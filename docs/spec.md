# Coverity トリアージエージェント 仕様書（策定中）

## 0. 目的（最優先事項）

これまで人間が実施してきた Coverity 警告のトリアージ作業を代替し、**人間の作業工数を削減する**こと。
以降のすべての仕様判断はこの目的に照らして行う。

## 1. 前提（キックオフで確定）

| 項目 | 内容 |
|---|---|
| エージェント基盤 | GitHub Copilot |
| 準拠仕様 | agent plugin 1.0.0（GitHub Copilot のエージェントプラグイン形式） |
| スクリプト言語 | Python |
| 対象 VCS | git / svn |
| 処理概要 | API でユーザ指定条件にマッチする CID を取得し、警告内容とソースコードを調査してトリアージ結果を出力する |
| 出力の特徴 | 警告内容にかかわらず「ソースコード修正案」と「逸脱コメント（トリアージコメント）案」の**両方**を出力し、人間がどちらを選ぶか判断しやすい情報を添える |
| git での修正出力 | 修正ブランチを作成する |
| 想定構成 | agent.md / SKILL.md / MCP / Python スクリプト等（詳細は相談しながら決定） |

## 2. 決定事項

| No | 項目 | 決定内容 |
|---|---|---|
| D-1 | プラグイン仕様 | GitHub Copilot のエージェントプラグイン形式に準拠する |
| D-2 | 実行形態 | VS Code（エージェントモード）と GitHub Copilot CLI の**両対応** |
| D-3 | Coverity 製品 | Coverity Connect（オンプレ） |
| D-4 | SVN での修正コード出力 | CID ごとに `svn diff` 形式の差分ファイル（`svn patch` で取り込み可能）を出力し、あわせて修正後ファイルをワーキングコピーのディレクトリ構造を保ったまま別領域に出力する |
| D-5 | 対象言語 | C / C++（それ以外の言語は将来対応） |
| D-6 | 対象チェッカー | Coverity 標準チェッカー、MISRA C / C++、CERT C / C++ |
| D-7 | エージェントが案を出す項目 | Classification、Action、Severity、コメント（逸脱理由）。現行の人間のトリアージ項目と同じ |
| D-8 | Coverity への書き戻し | 人間の承認後に書き戻す（承認なしの自動書き戻しはしない） |
| D-9 | 検証環境 | エージェント実行環境でビルドおよび Coverity 再解析（cov-build / cov-analyze）が可能 |
| D-10 | 修正案の自動検証 | オプションとする（実行時に「検証なし / ビルドのみ / ビルド＋再解析」を選択可能） |
| D-11 | 対象 CID の指定方法 | 絞り込み条件で指定する（CID の直接指定・保存済みビュー・自然言語指定は採用しない） |
| D-12 | 絞り込み条件の項目 | プロジェクト / ストリーム、チェッカー名、Impact、トリアージ状態（Classification / Action / Status） |
| D-13 | 絞り込み条件の入力方法 | 条件ファイル（YAML など）で指定し、必要に応じてチャットで条件を追加・上書きできる |
| D-14 | 1 回の処理件数 | 場合による（少数の日常運用と大量の一括処理の両方を想定） |
| D-15 | 大量処理への対応 | 1 回の実行の上限件数を設定可能とし、進捗をファイルに記録して中断・再開（処理済み CID のスキップ）に対応する |
| D-16 | 解析リビジョンとの整合 | 原則として Coverity が解析したリビジョンのコードで調査する。それができない場合は手元のコードを使い、解析時とのずれを検出してレポートに明記する |
| D-17 | 解析リビジョンの特定方法 | 次の優先順で使う。(1) スナップショットに記録されたリビジョンを自動取得する（記録する項目は設定で変更可能）(2) 記録が無ければ条件ファイル等でユーザが指定したリビジョンを使う (3) どちらも無ければ手元のコードを使い、ずれを検出して報告する（D-16）。なお現状はスナップショットにリビジョンを記録していないが、記録する運用に変更可能 |
| D-18 | レポート形式 | Markdown。CID ごとの詳細レポートと、全体の一覧サマリを出力する |
| D-19 | 承認と書き戻しの方法 | 人間がレポート（Markdown）の承認欄に「修正 / 逸脱 / 却下」を記入し（内容の手直しも可）、書き戻しを指示すると承認済みの CID だけ Coverity に登録する |
| D-20 | CID ごとのレポートの内容 | 必須：修正案、逸脱コメント案、Classification / Action / Severity 案。判断材料：真偽の見立てと根拠（警告経路の追跡結果）、推奨案と確信度（高 / 中 / 低）、修正の影響範囲とリスク、自動検証の結果（実施した場合） |
| D-21 | 逸脱コメントの書式 | 社内の既存書式は無いため、本仕様で定める（D-22〜D-24） |
| D-22 | 逸脱コメントの言語 | 日本語 |
| D-23 | 逸脱コメントの要素 | 必須：判定区分（誤検知 / 意図的 など）、理由。追加：コード上の根拠箇所（ファイル・関数・行）、影響がないことの説明 |
| D-24 | 逸脱コメントの体裁 | 見出しを付けない文章形式（例：「誤検知。get_buf() の戻り値は NULL になり得るが、呼び出し元 read_all()（src/io/reader.c:120）で NULL を除外してから渡しているため、当該経路で NULL 参照は発生せず動作・安全性への影響はない。」） |
| D-25 | git の修正ブランチの単位 | 設定で選択する。(a) CID ごとに 1 ブランチ (b) 実行ごとに 1 ブランチ（CID ごとに 1 コミット） |
| D-26 | git での差分ファイル出力 | ブランチに加えて、SVN と同じく CID ごとの差分ファイル（.patch）も出力する |
